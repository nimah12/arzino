# ارزینو (Arzino) — قیمت لحظه‌ای ارز، طلا و سکه

پنل نمایش قیمت لحظه‌ای ارز، طلا و سکه به زبان فارسی/انگلیسی، با تم روشن/تیره، نمودار، جستجو و به‌روزرسانی خودکار. داده‌ی واقعی از وب‌سرویس [نوسان (Navasan)](https://navasan.tech) دریافت می‌شود.

---

## ✨ امکانات

- **قیمت زندهٔ ۱۰ دارایی**: دلار، یورو، پوند، درهم، لیر، طلای ۱۸ عیار، طلای آب‌شده (مثقال)، سکه امامی، نیم‌سکه و تتر (USDT).
- **دو زبانه (فارسی/انگلیسی)** با اعداد فارسی/لاتین و جهت RTL/LTR — انتخاب کاربر ذخیره می‌شود.
- **تم روشن/تیره** با ذخیرهٔ انتخاب و تشخیص خودکار تم سیستم (بدون پرش هنگام لود).
- **جدول واچ‌لیست**: قیمت، خرید/فروش (دلار)، تغییر ۲۴ ساعت، نمودار اسپارک‌لاین و زمان آخرین به‌روزرسانی هر دارایی.
- **نمودار بزرگ** با کلیک روی هر اسپارک‌لاین (مودال).
- **جستجوی زنده** میان دارایی‌ها.
- **فلش سبز/قرمز** قیمت هنگام تغییر بین رفرش‌ها.
- **کارت‌های خلاصهٔ بازار** (دلار، تتر، طلای ۱۸، سکه امامی).
- **پیام خطای واضح** وقتی کلید API نامعتبر است یا سرویس در دسترس نیست.
- **کانت‌داون تا رفرش بعدی** تا کاربر بداند داده فقط هر ۸ ساعت به‌روز می‌شود.
- **فونت وزیرمتن (Vazirmatn)** به‌صورت محلی (self-hosted) — بدون وابستگی به Google Fonts.
- **آیکون‌های Lucide** به‌جای SVG دستی — طلا با رنگ طلایی (`--gold`) و ارزها با رنگ اصلی (`--accent`)؛ برچسب کارت‌های خلاصه هم‌رنگ آیکون است و هدر جدول یک خط گرادیان accent→gold دارد. حالت یکدست با prop `uniform` قابل بازگشت است، رنگ با prop `color` از بیرون قابل تنظیم است، و با هاور روی هر آیکون، نام دارایی به زبان فعال (فارسی/انگلیسی) به‌عنوان tooltip نمایش داده می‌شود.

## 🔑 منبع داده: وب‌سرویس نوسان (Navasan)

قیمت‌ها از `https://api.navasan.tech/latest/?api_key=...` خوانده می‌شوند.

- **کلید API**: به‌صورت پیش‌فرض در `src/lib/navasan.ts` است و از طریق متغیر محیطی `NAVASAN_API_KEY` قابل جای‌گذاری است.
- **پلن رایگان**: ۱۲۰ درخواست در ماه. برای همین برنامه حداکثر **۳ بار در روز** (هر ۸ ساعت) به API درخواست می‌دهد تا سهمیهٔ ماهانه (۹۰ درخواست) نسوزد.
- **واحدها**: ارزها و طلای ۱۸ عیار به **تومان** و سکه‌ها و مثقال طلای آب‌شده به **هزار تومان** گزارش می‌شوند؛ در `PRICE_SCALE` (`src/lib/navasan.ts`) ضریب ×۱۰۰۰ برای این نمادها اعمال شده است.

## ⏱ معماری کش و محدودیت ۳ بار در روز

به‌دلیل سهمیهٔ رایگان نوسان (۱۲۰ درخواست/ماه)، داده‌ها به‌صورت محافظه‌کارانه کش می‌شوند:

1. **بازهٔ ۸ ساعته** (`REFRESH_MS` در `src/lib/prices-server.ts`): بعد از هر تلاش موفق یا ناموفق، تا ۸ ساعت به API درخواست جدیدی ارسال نمی‌شود.
2. **ذخیره روی دیسک**: کش و وضعیت (داده، زمان کش، زمان آخرین تلاش، زمان آپدیت نوسان، وضعیت خطا) در `var/arzino-cache.json` ذخیره می‌شود. با ری‌استارت سرور، اگر هنوز ۸ ساعت نگذشته باشد، API اصلاً صدا زده نمی‌شود. **بافر لحظه‌ای (تاریخچهٔ نمودارها) هم در همین فایل ذخیره می‌شود** (حدوداً هر دقیقه یک‌بار، هم‌گام با رشد بافر) تا تاریخچهٔ نمودارها هم بعد از ری‌استارت از بین نرود. این فایل در `.gitignore` است.
3. **خطا هم محدود است**: اگر کلید نامعتبر باشد یا درخواست خطا بدهد، تلاش مجدد هم فقط هر ۸ ساعت انجام می‌شود (تا کلید به‌خاطر ریکوئست‌های تکراری مسدود نشود).
4. **سرویس‌دهی به کلاینت**: UI هر ۱ دقیقه از سرور خودمان (`/api/prices`) می‌گیرد؛ سهمیهٔ نوسان هیچ‌وقت با رفرش صفحه‌ها مصرف نمی‌شود. کانت‌داون «بروزرسانی بعدی» دقیقاً همین بازه را نشان می‌دهد و رفرش زودهنگام فقط یک پیام آموزشی نشان می‌دهد.

### رفتار خطا

- کلید نامعتبر → بنر قرمز: «کلید API نامعتبر است … (تلاش مجدد هر ۸ ساعت)».
- قطعی سرویس/خطای شبکه → بنر قرمز: «دریافت قیمت‌های زنده ناموفق بود …».
- در همهٔ حالت‌های خطا، جدول با fallback (خط تیره) پر می‌شود تا چیدمان حفظ شود.
- بعد از موفقیت، خطا پاک و قیمت‌های واقعی جایگزین می‌شوند.

## 📊 دربارهٔ نمودارها

سرویس نوسان تاریخچهٔ قیمت ارائه نمی‌دهد، اما سرور خودمان یک بافر لحظه‌ای نگه می‌دارد: هر بار که کلاینت از `/api/prices` بگیرد، یک نمونهٔ دقیقه‌ای برای هر دارایی ثبت می‌شود (حداکثر ۲۴ ساعت). پاسخ `/api/prices` این تاریخچه را در فیلد `history` هر دارایی برمی‌گرداند.

- **مودال نمودار بزرگ و اسپارک‌لاین‌های جدول**: وقتی بافر حداقل یک نمونهٔ واقعی داشته باشد، همان دادهٔ واقعی رسم می‌شود و با یک دنبالهٔ کوتاه نمایشی به قیمت فعلی می‌رسد. فقط وقتی بافر **خالی** است (مثلاً بلافاصله بعد از ری‌استارت) به منحنی مصنوعی برمی‌گردند. زیر نمودار بزرگ هم برچسبی نمایش داده می‌شود: «نمونه‌های واقعی: N · X دقیقهٔ گذشته» تا کاربر بداند داده واقعی است (یا پیام «منحنی نمایشی» وقتی بافر خالی است). توجه: چون دادهٔ نوسان هر ۸ ساعت به‌روز می‌شود، خط تاریخچه در طول همان بازه تقریباً صاف است و بعد از هر رفرش ۸ ساعته جابه‌جایی واقعی را نشان می‌دهد.
- **منحنی مصنوعی (فقط بافر خالی)**: یک منحنی صاف و قطعی (deterministic) حول قیمت فعلی که در بازهٔ منطقی ±۱–۲٪ قیمت باقی می‌ماند و جهت کلی آن با «تغییر ۲۴ ساعت» واقعی هم‌راستاست (▲ صعودی / ▼ نزولی).
- انیمیشن رسم خط هر ۱ دقیقه (با تیک ساعت) تکرار می‌شود تا حس «زنده» بودن حفظ شود.

## 🧪 تست‌ها

تست‌های واحد با **Vitest** نوشته شده‌اند و بدون صدا زدن API واقعی اجرا می‌شوند:

```bash
npm test
```

- `src/lib/prices-server.test.ts` — منطق کش ۸ ساعته را با mock کردن درخواست شبکه به نوسان تست می‌کند: اولین fetch، سرویس‌دهی از کش در بازهٔ ۸ ساعت، رشد تاریخچهٔ live، fetch مجدد بعد از انقضا، throttle خطا (کلید نامعتبر → fallback → تلاش مجدد بعد از ۸ ساعت) و بقای کش + تاریخچهٔ live بعد از ری‌استارت (بازیابی از دیسک بدون درخواست اضافه). زمان با اسپای `Date.now` کنترل می‌شود و فایل کش در یک پوشهٔ موقت ساخته می‌شود تا به `var/` واقعی دست نزند.
- `src/lib/jalali.test.ts` — تبدیل تاریخ میلادی → شمسی با تاریخ‌های شناخته‌شده (نوروز ۱۴۰۳، انقلاب ۲۲ بهمن ۱۳۵۷ و…) و قالب‌بندی تاریخ فارسی/انگلیسی.
- `src/lib/prices.test.ts` — تبدیل ارقام فارسی/لاتین، قالب‌بندی تغییر ۲۴س و قیمت با جداکنندهٔ هزارگان (و رفتار «—» برای مقادیر خالی/صفر).
- `src/lib/api-prices.integration.test.ts` — تست یکپارچه‌سازی `GET /api/prices` با **supertest** روی route واقعی (با `NextResponse`): شکل کامل پاسخ (data/dataTime/error/nextRefresh)، رفتار کلید نامعتبر (fallback + خطا) و سرویس‌دهی از کش ۸ ساعته با فقط یک درخواست بالادستی. برای این که route مستقیم در vitest ایمپورت شود، alias «@» در `vitest.config.ts` تنظیم شده است.
- `src/app/components/PriceChart.test.ts` — تست `blendSeries`: حفظ نمونه‌های واقعی، افزودن دنبالهٔ ۱۴ نقطه‌ای، همگرایی به قیمت فعلی، قطعی بودن (deterministic) و کار با ساختار `{t,p}` همان‌طور که نمودار استخراج می‌کند.
- `src/lib/jalali.test.ts` — شامل تست `formatTimeSpan` (بازهٔ زمانی خوانا: دقیقه/ساعت/روز در فارسی و انگلیسی).

**تست بصری (E2E)** با Playwright (`npm run test:e2e`): مودال نمودار بزرگ را در هر دو تم روشن/تیره با دادهٔ ثابت (mock) باز می‌کند و بررسی می‌کند رنگ خط نمودار با نشان «تغییر ۲۴س» (▲ سبز / ▼ قرمز) و رنگ آیکون دارایی (طلا → `--gold`، ارز → `--accent`) مطابقت دارند و از هر تم اسکرین‌شات می‌گیرد (`test-results/modal-{dark,light}.png`). در محیط‌هایی که CDN مرورگر Playwright مسدود است (مثل ایران)، محلی از مرورگر نصب‌شدهٔ سیستم (Edge/Chrome) استفاده می‌شود.

CI (GitHub Actions) تست‌های واحد را به‌همراه تایپ‌چک، lint و build، و تست‌های E2E را در یک job جدا روی هر push اجرا می‌کند.

## 📝 نکات توسعه

- **ماژول‌های سرور/کلاینت جدا هستند**: `prices-server.ts` از `fs` استفاده می‌کند و هرگز وارد باندل کلاینت نمی‌شود؛ `prices.ts` فقط تایپ و تابع‌های نمایشی دارد.
- اگر کش را دستی تست می‌کنید: `rm -f var/arzino-cache.json` و سرور را ری‌استارت کنید تا یک درخواست واقعی به نوسان برود.
- نسخهٔ کش (`CACHE_VERSION`) با تغییر ساختار داده تغییر می‌کند تا کش‌های قدیمی نادیده گرفته شوند.
